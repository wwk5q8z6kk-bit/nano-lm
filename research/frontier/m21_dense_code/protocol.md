# Prospective protocol for repository-disjoint code modeling

Does Antigravity M21 improve code prediction relative to a competitive full-attention Transformer at the same size, number of updates and sampled tokens? A positive result would justify a separate distribution and scale study. This is an exploratory training comparison.

Use M21 from the register study, including its native annealed auxiliary base-head objective, and the attention-only GQA implementation from discovery-lab revision `3314170a8c9ca4e19445496fc27d40a631ac0063`. Both have four layers of width 128, with a tied 32,768-token vocabulary. M21 has 5,046,637 parameters, dense GQA has 5,046,656. The dense model uses four query heads, two KV heads, RoPE, learned QK RMSNorm and SwiGLU width 426. Initialize each architecture from its own native constructor, seeded with 1000 + 97 times the seed.

Use the pinned row-license-screened CodeParrot data and tokenizer hashes in corpus.json. Verify both token/metadata files, whole-document lengths, unique content and train/validation repository separation. Uniformly sample eligible 129-token windows, with replacement across positions and no document boundary crossings. Windows end with a real target, possibly an end-of-document token. Use PCG64 with seed 70000 + 131 times the seed. Save an ordered sampled-offset digest. Use seeds 0, 1, 2, running M21 first on the even seeds and GQA first on seed 1. Use one device, fp32, fixed AdamW defaults (betas 0.9/0.999, eps 1e-8, decay 0.01), gradient norm clipped to 1, 4,000 steps × 8 × 128 predictions. Warm up for 400 updates to LR 0.0015, cosine-decay to 10% of peak. M21's base-head auxiliary weight cosine-decays from 0.25 to zero. All six fits finish before inspecting held-out model scores. Report all cells. Record wall time and the first 100-step rate on the same fits.

Score each within-file next-token target exactly once, including the final delimiter, at context up to 128; start a new context every 128 predictions and at every file boundary. Right-pad only after valid targets and mask padding from all summaries. Primary endpoint is pooled bits per scored token with log-normalization for both architectures. Report equal-repository macro bits per token, each seed, and exact corpus counts. Record original token stream size and decoded UTF-8 bytes, label and document-length strata (at most 512 tokens, 513 to 2048, over 2048), and whether the correct label appears among M21's valid sparse pointer candidates at that position. Score the M21 base head on the same weights/positions as a diagnostic. Each model's training loss includes its architectural choices, so a gap cannot be attributed to recurrence or the pointer individually.

Define gain as dense bits/token minus M21 bits/token. Select a future independent comparison only when all seeds have positive pooled gain, mean gain is at least 0.02 bits/token, and a two-sided 95% percentile interval for mean repository gain has lower endpoint above zero. Bootstrap 329 repository groups with replacement from the matched observations, retaining the three seed pairs within each group; use 10,000 samples with PCG64 seed 22026. This interval describes variation across held-out repositories conditional on the three fitted seeds. The screen trains on 4.096M predictions per cell, reuses a tokenizer derived from upstream training shards, and covers a single code distribution. No architectural choice or threshold will be selected on these validation scores.
