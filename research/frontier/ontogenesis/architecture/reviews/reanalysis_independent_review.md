**Scope:** review of `analysis/reconcile_repository_evidence.py`, `results/repository_reanalysis_v3.json`, frozen `evidence/upstream/correction_interference.py.txt`, its imported world constants, and the frozen result JSON files. This review did not fit a neural model, rerun historical training, or change those files.

## Verdict

The reported RNG divergence is correct, and the compact diagnostic faithfully follows the frozen source's NumPy draw order. The solver-status collapse is also a real source defect. The correction-cohort mismatch requires careful interpretation, but does not erase all evidence of lost corrections.

I independently extracted the actual frozen `run()` function by AST, inserted a capture after correction-list construction, and substituted a no-op model whose fit method performs no work. This executed the original data/control flow for `single`, `entity_replay` and `random_replay` without importing or training its Torch model. Captured event arrays matched the diagnostic for all nine arm/seed combinations. Re-evaluating the reanalysis report reproduced the frozen JSON semantically.

## 1. Random replay changes future treatment-independent events

The original function creates one NumPy generator, draws the world and shown mask, then uses that generator both for correction identities/values and random replay selection. The extra `rng.choice(...)` in the random-replay branch changes the generator state before the next correction phase. Consequently the initial world is matched, but subsequent correction streams are not.

**What remains supported:** single versus same-entity replay uses identical worlds, initial model seeds and exogenous correction events under the source contract. Its immediate-locality comparison is not affected by this RNG defect. The historical random-replay results are still observations from a randomized stream generated by the program; their values need not be false or have zero expected effect.

**What is not supported:** seed-paired contrasts that claim the random-replay arm received the exact same correction events, or a strong claim that its difference from another arm isolates replay location alone on a common realized stream. A shared pseudorandom generator is not automatically evidence of systematic bias, but it removes the intended pairing and adds uncontrolled realized-stream variation to a three-seed comparison. Reanalyzing the existing aggregates cannot recreate the missing matched-stream outcome.

The same-entity arm also trains on additional facts compared with `single`; the supported intervention is same-entity rehearsal plus those exposures. A cost-equated random-replay control is useful, but this implementation does not provide a fully paired stream for that comparison.

### Repair contract

1. Preserve the old source and results as history.
2. Generate an immutable world and correction-event schedule before selecting an arm, using the original single-arm draw order if backward comparability is desired.
3. Give replay sampling a separate named RNG stream, preferably determined by seed, purpose and phase. Do not derive it from a generator advanced by arm-specific operations.
4. Make every arm consume the same event-file hash and record that hash in every result.
5. Apply events to working truth in phase order. **Do not precompute a final truth array and accidentally expose future corrected labels during earlier replay.**
6. Add a control-flow test that changes the number of replay draws and still obtains identical future correction schedules.
7. State whether correction targets may equal their current value. The old sampler permits no-op corrections; forcing a different value would be a new protocol.

An auditable interface is `make_world_and_events(seed, config) -> initial_world, events`, followed by `replay_keys(seed, phase, eligible_keys, count)`. The learner receives only the initial state and events up through the current phase.

## 2. Solver success and infeasibility are conflated

The frozen `address_edit()` returns `(None, False)` for every nonzero `linprog` status, while its docstring describes that result as infeasibility. The controlled-status probe correctly demonstrates identical returns for status 2 and status 4. No claim is made that status 4 actually occurred historically.

The [official SciPy HiGHS documentation](https://docs.scipy.org/doc/scipy/reference/optimize.linprog-highs.html) distinguishes successful optimization, a reached iteration/time limit, apparent infeasibility, apparent unboundedness, and a solver problem. Thus historical `lp_feasible` is most accurately a **solver-success fraction**, because the saved JSON has no status breakdown or feasibility residuals.

Even genuine infeasibility would apply only to the formulated address-only, fixed-decoder, specified-margin constraints at that snapshot. It would not prove the whole model class cannot represent the facts or that external storage is necessary.

### Repair contract

Return a structured result containing raw status/message, solver/version/options, outcome class, iterations, delta and residual diagnostics. Classify at least `optimal_validated`, `reported_infeasible`, `limit`, `reported_unbounded` and `solver_error`; reserve `unknown` for anything else.

For status 0, check finite values, nonnegative split variables within tolerance and `max(A @ x - b)`. Then apply the delta at the model's actual storage dtype and recheck every protected margin and target prediction. A float64 LP solution followed by a float32 parameter update is not automatically a validated deployed edit. If a formally certified infeasibility claim is needed, retain the relevant certificate or independently checked dual witness; a boolean return alone is insufficient.

Preserving other relations' **current model answers** is also distinct from preserving correct facts. The constrained arm's stated optimization targets the former.

## 3. Correction acquisition and delayed scoring use different cohorts

`corrected_now` averages 39 phase scores, each covering 16 correction events: 624 event observations per seed. An event may repeat a previously edited key. `corrected_old` is one final score over unique keys whose **latest** correction occurred at least 20 phases earlier. Keys edited again late leave that final cohort; superseded earlier values are not the final target.

Therefore `corrected_now - corrected_old` is not a paired same-cohort decay estimate, a survival curve, or a direct estimate of a particular edit's longevity.

**Important qualification:** for the single, entity-replay and frozen-address arms, the reported immediate mean is 1.0000. Under the fixed 624-event source contract, rounding to four decimals cannot conceal even one immediate error: one error would lower the mean by about 0.0016. Their final old-correction scores below 1 therefore still support some loss of previously acquired, unsuperseded corrections. The cohort mismatch limits the magnitude and temporal attribution of “decay”; it does not justify claiming there is no durability evidence.

For the constrained arm, an immediate mean of 0.9984 is consistent with one failed immediate event per seed under the same contract. Its much lower delayed score is concerning, but an exact event-level forgetting estimate still requires cohort membership, denominators and trajectories.

### Repair contract

Log immutable edit IDs, entity/relation, old and new target, phase, whether the value actually changed, immediate correctness, later correctness at fixed lags, and supersession. Evaluate each edit version only while it remains the intended current truth. Report retained-success rates conditional on immediate acquisition, with event/seed denominators, uncertainty and censoring/supersession policy. Keep a separate final current-facts score.

## 4. Further interpretation details found in the same source

- `random_replay` excludes entities corrected **in the current phase**, not every entity ever corrected. The code comment calling them “uncorrected entities” is broader than the actual eligibility rule.
- `collateral_now` excludes all previously corrected relations on the currently corrected entities. It is accuracy on their never-corrected shown facts, not accuracy on every other relation.
- `same_type_now` can count the same eligible fact multiple times when several correction events contribute overlapping comparison sets. Its denominator is comparison occurrences, not necessarily unique facts.
- Only aggregated results were saved. Some denominators can be reconstructed conditionally from the pinned source/schedule, but model prediction trajectories and historical solver statuses cannot.

## Suggested evidence language

“The source audit confirms matched correction streams for single and same-entity replay and supports the observed immediate-locality advantage of the latter in this bilinear world. The random-replay arm advances the correction RNG through replay sampling, causing different future corrections from phase 2 onward in all three seeds; its cross-arm results should not be treated as paired same-stream controls. Successful immediate acquisition and lower final old-correction accuracy indicate a durability problem, while the two metrics' different cohorts prevent interpreting their subtraction as a paired decay rate. The constrained arm records solver success rather than fully classified feasibility certificates.”
