## Mechanism findings

| Review question | Source finding | Interpretation |
|---|---|---|
| Do branches start equally? | A shared 40-step common-prefix run supplies copied parameter arrays, first/second Adam moments, step number and optimizer configuration; equality is checked by state digest | No optimizer reset or array alias is intended between arms |
| Can a learner access hidden future values through its interface? | `observe` accepts only the next `VisiblePrefix`, checks the exact observed event tuple and verifies its latest-target table | Training sees delivered values only; this is interface discipline, not a Python isolation boundary |
| Are hidden labels causally separate? | Unobserved random-label targets are generated by a dedicated coordinator RNG; model initialization uses a separate generator and replay is deterministic | Hidden-label changes have no intended route into training or logits |
| Is replay stale or secretly oracle-selected? | It chooses the latest delivered revision per key, excludes the current key, prioritizes another same-entity key, then uses a deterministic other-entity fallback | Selection uses available history and never loss, success or future labels |
| Are fallback exposures visible? | Same-entity, other-entity and no-other-key current-repeat fallbacks have separate counters and event IDs | The fixed main comparison should use 24 same-entity and 12 other-entity replay steps per replay arm/seed; the last fallback is fixture-tested |
| Are outputs actual model predictions? | Inference receives only entity/relation/marker tokens; it takes the argmax over all 22 native vocabulary logits | No lookup oracle or restricted four-label classifier substitutes for the native head; non-value output counts as abstention |
| When is acquisition measured? | Prediction is taken after the complete event update transaction, including the replay step if present | Immediate acquisition includes any within-transaction replay interference |
| Are failed acquisitions removed? | All assignment-event horizon cohorts remain primary; acquired-only rates are separate | Retention is not inflated by conditioning primary results on successful initial learning |
| Are revisions/censoring explicit? | The inherited `new_revision` policy censors superseded assignment events; same-value assignments remain a separate recorded stratum | Event identity is preserved even if the value did not change |
| Are artifacts protected? | CLI refuses existing/dangling-symlink output before running; report writing uses exclusive creation | The intended path preserves previous receipts |

The primary descriptive endpoint is all-assignment phase-end horizon 1 accuracy. Immediate-after-transaction measurement and phase-end horizon 0 are distinct. With only seven phases, horizons 10 and 20 cannot become due; null denominators and explicit not-yet-due/censored counts are the right output, not zero-filled accuracy. The fixed seed summary suppresses an aggregate when any seed endpoint is undefined.

## Cost and exposure assessment

The common prefix contains four observed facts and is trained for 40 batch updates per seed: 160 scored target presentations and 480 input-token presentations. It executes once and is cloned into all arms. There are 36 post-prefix events per seed, comprising 24 initial observations and 12 assignments.

| Post-prefix arm, per seed | Current presentations | Replay presentations | Total optimizer calls / scored targets | Training input-token presentations |
|---|---:|---:|---:|---:|
| Current only | 72 | 0 | 72 | 216 |
| Replay, matched total | 36 | 36 | 72 | 216 |
| Replay, additive | 72 | 36 | 108 | 324 |
| Frozen | 0 | 0 | 0 | 0 |

The matched-total comparison truly matches update calls, full-length input shapes and total scored-target presentations. It changes which targets receive those updates. Additive replay preserves current-target exposure while spending 50% more post-prefix updates. Frozen is a no-learning reference. None of these equalities makes replay selection, memory, kernel work or elapsed time equal; the protocol and output correctly avoid that stronger claim.

For the main three-seed comparison, the source predicts 120 common-prefix plus 756 post-branch optimizer calls, or 876 total calls, and 480 plus 756 scored targets, or 1,236 presentations. There are 204 inference calls per arm/seed: 36 event predictions, 112 observed-fact phase-end queries and 56 hidden-control queries. These are source-derived expectations to compare with execution spies, not measurements reported by this reviewer.

Every arm retains full delivered history for audit purposes. The replay payload count represents a canonical latest-target table needed by the algorithm; it is not incremental measured process RAM. Parameter and Adam array sizes exclude activations, allocator overhead, Python objects and peak workspace. This distinction is correctly stated in the output. Test counterfactuals and repeat runs also consume computation and must be reported separately from the main comparison's counts if a total validation-work figure is presented.

## Test review and limits

The tests cover branch equality and nonaliasing; spy actual training documents, masks and forward outputs; compare scheduled and observed update/query counts; reject malformed prefix tables before mutation; test replay priority and all fallback categories; preserve full cohort partitions; perturb future values and private hidden labels; repeat one seed/arm; and verify exclusive artifact writes. The counterfactuals require identical earlier states/logits rather than equal aggregate accuracy, which is appropriate for causality. They do not demand a favorable model result.

`setUpClass` executes the full comparison. The reviewer therefore inspected it without invoking unittest before the coordinator's execution. Source hashes are the handoff boundary: a later implementation/protocol change requires a new review or an explicit amendment. This is a source-level readiness finding; successful runtime receipts, substantive outcome interpretation and publication remain separate steps.
