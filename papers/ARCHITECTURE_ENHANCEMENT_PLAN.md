## 1. Architecture as it stands

**Core (`nano_ai/` — contract, solver boundary, adapters, instruments).** This is the strongest code in the repo. `nano_ai/contract.py` (532 lines) makes an ungrounded output *unconstructible*: SUPPORTED requires a span whose `normalize_value(span.text)` equals the value; ABSENT requires a span matching a per-field denial pattern; CONFLICTING requires two spans distinct in both offsets and normalized text; every span is re-validated against the transcript and must fall inside a `Patient:` line. `nano_ai/solver.py` fails closed with seven typed failure categories and re-reads the descriptor before and after inference to catch identity drift. `nano_ai/evaluation.py` refuses to collapse quality into a scalar and already ships a full 5×5 `state_confusion`; `nano_ai/benchmarking.py` re-derives the primary metric from item rows rather than trusting the evaluator. The honest weaknesses are three: the "independent verifier" used by the H-cycle adapters is `deterministic_v0._extract_fields` — the same rules-perfect template extractor that scored 1100/1100, imported privately at `nano_ai/adapters/state_span.py:275` and `pointer_span.py:161`; `benchmarking._diagnostic_rows` raises on any protocol other than `legacy-summary-diagnostics-v0`, so the frozen aggregator cannot score any post-H1 solver; and the test pyramid is inverted — 38 test functions guard ~4,100 lines of load-bearing core while ~338 guard disposable per-hypothesis scripts. There is no `.github/`, no ruff or mypy config.

**Training (`nano_ai/training/`, 27,764 lines).** Architecture is 3.8% of it (1,051 lines) and is correct: RoPE pairing/broadcast, GQA head-group mapping, and SwiGLU gate ordering all check out by hand. Provenance machinery is genuinely excellent — read-once byte snapshots, `hmac.compare_digest`, `open("xb")`+fsync, input-hash re-verification at four points inside a single run, checkpoints that re-read their own bytes. The stack is verified everywhere *except on numerics*. There is no weight initialization at all in `nano_ai/training/model.py` (masked today only because every path warm-starts); a grep across `nano_ai/` for `sdpa_kernel|SDPBackend|allow_tf32|cudnn.deterministic` returns empty while the training report writes `"deterministic_algorithms": True` as a literal claim; and every one of the 13 trainer-candidate call sites in `nano_ai/tests/` sits inside `pytest.raises`, so no test has ever completed a training step. The H4/H5/H6 generation triplets are 87–98% identical to each other, but their SHA-256s are pinned by `PRESERVED_H3_SOURCE_SHA256`, so consolidation must be additive-forward or it invalidates the artifacts it authenticates.

**Pretraining (`nano_ai/pretraining/`, 583 lines, 5 tests).** Atomic-write discipline is right: partial→fsync→rename at both shard and directory level, a manifest of hashes plus a hash of the manifest, verify-before-yield in `ManifestTokenDataset`, fail-closed budget exhaustion, `deepcopy` in `source_record`. The defects are concentrated and confirmed. `prepare_dataset` does `os.replace(staging, output)` *before* `verify_prepared_dataset`, and its `except` branch `rmtree`s a path that by then no longer exists — a verify failure publishes a broken dataset under its real name and deletes nothing. `pretrain/tokenizer.json` registers `<|endoftext|>` as an *added* token, so `encode('hello <|endoftext|> world').ids == [259,298,79,221,0,962]` with or without `add_special_tokens=False`; since `prepare.py:126` appends `EOD_TOKEN_ID = 0` per document, web text containing that literal injects phantom document boundaries — and the test double (`ord(c) % 251 + 1`) can never emit 0, so the suite structurally cannot catch it. `prepare.py:231-232` hardcodes `"vocabulary_size": 4096` into the manifest. Authorization is a one-string whitelist at `prepare.py:178` with no token cap, so a 3.2B-token run is already preparable under the "bounded smoke" state, and `blocking_gates` / `private_or_development_data` are prose that no code reads. `_stream_fineweb_edu` — the newest and subtlest logic — has zero tests.

**Fabric (`fabric/`, 526 lines, 8 tests).** The smallest and most conceptually load-bearing body. `fabric/schemas.py` enforces VERIFIED-requires-span and `¬Found(x) ⇏ ¬x` in constructors, uses content-addressed IDs, and carries a runnable self-test. `grounding.v1` (verbatim + role-aware) is the transferable relation; `grounding.v2` is template-anchored — `fabric/slice.py:97` `exec`s a string-split prefix of `scribe/build_scribe_data.py` to harvest the generator's own lexicons, which is why fabric's README says outright that v2 "could solve the task alone." The frozen gate at `fabric/slice.py:247-248` computes `presented_err / max(1, presented)` and passes when `presented == 0` — an abstain-everything verifier reports 0.0% error and GATE PASS. And coverage is never reported: recomputed from `fabric/results_slice_v1.json`, v2's 0.0% runs at 81.5–91.0% field coverage and 76.2–91.0% end-to-end yield, while `PRODUCT_THESIS.md` and `NANO_V2_AMBITION.md` both quote the 0.0% with no denominator. `fabric/slice.py:210-214` writes untyped `{source, action: "review", ...}` dicts that bypass `Decision` and enter neither numerator nor denominator.

**Control plane (`artifacts/` + `~/.codex/skills/nano-runpod-operator/`).** The guard is 6,789 lines with a 3,968-line / 73-test suite. Its durability primitives are correct — O_EXCL one-shot markers, temp+rename+`fsync_directory`, a real `previous_sha256` chain with independent replay, per-run flock. The guard has no git history at all. **How they relate: they don't.** `grep -rn "from nano_ai|import nano_ai"` outside `nano_ai/` returns zero. Same for `wedge_v1` and `fabric`. The only linkages in the repo are two path hacks — `fabric/slice.py:27` loading `trajectory/rescore_anchors.py` via `spec_from_file_location`, and `trajectory/e1/methods.py:29` loading `fabric/slice.py` to reuse `_extract` as the E1-winning M1. `AGENTS.md` records this boundary as deliberate. The islands are not a bug to be merged; they are a bug to be *named*, so that the one path that is actually shipped (wedge_v1) is held to the invariants the thesis claims.

## 2. The convergence picture

The thesis is that the verification layer is the product and the model is the engine. Three things follow from what the code actually shows, and one thing does not.

**The verification layer is real, and it is over-tuned in one direction.** Fail-closed grounding is earned: `nano_ai/contract.py` and `fabric/schemas.py` both make an ungrounded assertion unconstructible, and `fabric`'s measured presented error is 0.0%. But the only non-fixture corpus ever tested — `wedge_v1/.studies/p5-repo-papers-20260802-r4/`, 10 real markdown documents, zero audit failures — records `first_repeated_failure_class: OVER_ABSTENTION`, 3 USEFUL / 4 CORRECT_ABSTENTION / 3 OVER_ABSTENTION, `representative_ready: false`. The product does not fail by hallucinating; it fails by withholding. Every architectural move that adds strictness is therefore currently *anti*-aligned with the measured failure, and every move that recovers a correct answer without weakening the gate is aligned. **The unified architecture must report abstention cost as a first-class number everywhere it reports error.** Fabric already computes `lost_correct`; the frozen `BenchmarkReport` does not; `wedge_v1` reports it only inside a study summary.

**Every headline number needs a denominator attached at the point of publication.** "0.0% presented error" is true and, without "at 81.5–91.0% coverage," misleading — and it appears without the denominator in both `papers/PRODUCT_THESIS.md` and `papers/NANO_V2_AMBITION.md`. A verification layer sold on honesty must report its own operating curve, not a single point. This is the cheapest structural alignment available and it is a documentation-plus-twenty-lines change.

**One verifier is transferable; one is not; say so in code, not only in prose.** `grounding.v1` (verbatim span + role containment) needs only role-segmented text and has a measured honest residual of 1.1–1.9%. `grounding.v2` `exec`s the generator's own template pools and cannot exist on a corpus we did not synthesize. The v2 number is a property of a closed world and must never be carried up the ladder. `nano_ai`'s H-cycle "verifier reduced false-presented fields to zero" results are the same shape — the verifier there is `deterministic_v0._extract_fields`, the rules-perfect reference extractor. The convergence move is not to unify them into a kernel; it is to keep the boundary and label which side of it each number was measured on.

**What convergence does *not* mean: a fifth schema.** The reviews independently proposed extracting a shared `nano_verify` / `verify/` kernel across the three trees. Verification killed it. There are already four typed-claim implementations (`nano_ai/contract.py`, `fabric/schemas.py`, `wedge_v1/coe/schema.py`, `wedge_v1/classical/solvers.py`), and two of the four ladder blockers the kernel was meant to remove are already absent: `wedge_v1/coe/schema.py:36` `EvidenceAtom` already carries `doc_id`, and `TypedClaim.raw_value` is `Any` with recursive leaf verification in `wedge_v1/coe/bind.py:75-124` — the compositional "every leaf traces to a span" rule the L2 proposals wanted to invent is implemented and running. The only genuine cross-tree duplication is `_semantic_fragments`/`_semantic_value_supported` cloned between `wedge_v1/coe/bind.py` and `wedge_v1/coe/audit.py`, and diffing them shows they are behaviorally identical *and* that `audit.py` is the independent auditor — sharing the code would destroy the independence that is its purpose. Under the standing "smallest sufficient solver" and "process frozen at current size" rules, the correct convergence is **naming, measuring, and testing what already exists**, not building a fifth home for it.

**Implication per tree.** `nano_ai` stays the contract-and-engine tree; it needs a mechanical net (property tests, lint) before any contract generalization, and its instruments need to report abstention cost. `fabric` stays the closed-world regression instrument; it needs its denominator and its degenerate-gate hole closed, and its invariant suite must stop dragging torch. `wedge_v1` is the only body with a product surface and is the only place the measured failure lives; it gets the diagnosis work. The control plane is infrastructure for a rung that is not yet funded; it gets exactly the irreversibility guards (seal, evidence index) and nothing else.
