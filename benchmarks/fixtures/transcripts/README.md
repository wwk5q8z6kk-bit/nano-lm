# Transcript fixtures

Checked-in inputs for `benchmarks/transcript_emitter.py`. The emitter is developed
and tested against **these files only**; it never reads `~/.claude/projects/`. The
one component that does is the validation experiment, which is a separate,
clearly-labelled script.

**These are instrument fixtures, not benchmark evidence.** They exist to show
that a transcript can be turned into a schema-valid action log with auditable
classification. They say nothing about the quality of any system, including the
one that produced them.

## Two kinds

| File | Kind | Tool calls | Why it is here |
|---|---|---|---|
| `synthetic_minimal.jsonl` | hand-built, real fake content | 13 + 1 orphan | exact-value tests: post-state reconstruction, reversion, line counts, timeout, orphan |
| `session_large_varied.jsonl` | sanitized real session | 269 | most tool kinds (11), full-session shape, heredoc-heavy Bash |
| `session_small_errors.jsonl` | sanitized real session | 14 | error-dense: 6 of 14 calls fail |
| `session_small_reads.jsonl` | sanitized real session | 10 | read-only investigation, no mutation |
| `session_trivial.jsonl` | sanitized real session | 1 | degenerate: one call, no Bash |

`synthetic_minimal.jsonl` is generated by `make_synthetic.py`; a test asserts the
checked-in file matches the generator. `MANIFEST.json` records the provenance of
each sanitized fixture (source chat and file prefix, raw and fixture sizes,
record counts).

A second large session (375 calls, 11 errors) was sanitized and then dropped: at
1.4 MB it doubled the fixture footprint, and its distinguishing property (error
density) is already covered by `session_small_errors`.

## What sanitization preserves and destroys

Produced by `benchmarks/transcript_sanitizer.py`. Regenerate with:

```bash
python3 -m benchmarks.transcript_sanitizer <raw.jsonl> benchmarks/fixtures/transcripts/<name>.jsonl
```

**Preserved** — everything the emitter classifies on: record type and order,
timestamps, `cwd`, tool names, tool `input` paths and flags, **shell commands in
full**, `tool_result.is_error`, the first line of error headers, and the
structural keys of `toolUseResult` (`interrupted`, `filePath`, patch hunk
geometry, diff prefix characters).

**Destroyed** — file bodies, prompts, model prose, thinking, edit strings, tool
stdout/stderr. Each is replaced by a marker

```
<redacted sha256=<16 hex> len=<N>>   followed by (lines − 1) newlines
```

that keeps two properties: *equality* (identical originals give identical
markers, so repeat and reversion detection on Writes still works) and *line
count* (so `lines_changed` for a created file matches the raw transcript).

**Consequence for Edit reconstruction.** The emitter recomputes a file's
post-state after an Edit by applying `oldString → newString` to `originalFile`.
On a sanitized fixture all three are markers, the substring is never found, and
the emitter falls back to a *derivation* digest and records `post_state:derived`
in the trace. A derivation digest cannot detect a reversion, so
`reversion_count` has false negatives on sanitized fixtures. Post-state
correctness is therefore tested on the synthetic fixture, where reconstruction
succeeds, and the raw-vs-sanitized invariant in the validation experiment
confirms that this is the *only* field on which the two disagree.

## What sanitization does not guarantee

Shell commands are kept because they are the classification signal. They pass
through a conservative credential-shape redactor (`SECRET_PATTERNS`), and a test
asserts no secret-shaped string survives in any fixture. That test is only as
good as the pattern list. **Every `command` string in a newly added fixture must
be read by a person before it is committed.** The four sessions here were.

The home directory is normalised to `~` everywhere a path can appear, including
inside commands and kept error lines; a test asserts no `/Users/` string survives.

## Invariant that makes the fixtures trustworthy

For every real transcript the validation experiment checks that

```
emit(raw)  and  emit(sanitize(raw))
```

agree on `seq`, `tool`, `action_class`, `targets`, `result_status`, token and
timing fields, `lines_changed`, `tests_run`, and the classification rule. On the
five sessions sanitized during fixture selection, 669 actions were compared and
the only differences were the expected `post_state:derived` notes on Edits.
